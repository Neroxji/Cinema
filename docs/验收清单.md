### 第一次小组会必须拍板的 8 件事

1. 选题最终确认（或换题；换题则第 0 节及后续细化全部重写）

## 一、选题与形态要求（P6 · 3.2）

- [ ] 至少 3 个子系统/功能模块，每模块 ≥1 名组员负责
- [ ] 业务复杂度足以体现 ≥3 种设计模式
- [ ] 实现为可编译、可运行的 Web 应用（不要求完整前端，核心业务逻辑可演示）
- [ ] 有现实意义，已规避"××信息管理系统"式简单题
- [ ] 自拟题已向老师确认"规模相当"

## 二、环境准备（P4-5 · 第1周）

- [ ] JDK + IDEA/Eclipse 安装配置可用
- [ ] MySQL（或演示用 H2）可用
- [ ] PlantUML + Graphviz 配好，能渲染出图
- [ ] Git 仓库建立，提交记录留全（个人贡献分佐证）
- [ ] 智能体工具注册 ≥1 款，开始记录使用 Log（见第七节）
- [ ] 组内分工表定稿（进报告封面"业务分工表"）

## 三、编码要求（P9 · 阶段四，第5周）

- [ ] 分层结构：controller / service / repository / model / util
- [ ] 设计文档中的类与方法在代码中真实存在（防"设计与代码两张皮"）
- [ ] 设计模式结构完整，无"伪模式"
- [ ] 关键类/方法标注：`// @Pattern: State, @UseCase: UCxxx`
- [ ] 项目可编译、无运行错误（**编译不过 = 编码 10 分全扣，P19**）
- [ ] 锁座并发三层防线落地：事务内先查后锁 + `@Version` 乐观锁 + (场次,座位)唯一索引
- [ ] 超时释放：`@Scheduled` 扫表 + 释放前防竞态复查

## 四、设计模式分析（P12-14 · 报告 15 分 + 答辩 7 分）

每种模式按 8 项模板（P13）逐项完成：

| 模式 | 分类 | UML结构 | 应用场景 | 核心代码 | 解决的问题 | OO原则 | 扩展性分析 |
|---|---|---|---|---|---|---|---|
| 状态模式（座位/订单） | 行为型 | ☐ | ☐ | ☐ | ☐ | ☐ | ☐ |
| 策略模式（票价） | 行为型 | ☐ | ☐ | ☐ | ☐ | ☐ | ☐ |
| 观察者模式（通知广播） | 行为型 | ☐ | ☐ | ☐ | ☐ | ☐ | ☐ |
| 命令模式（退改签） | 行为型 | ☐ | ☐ | ☐ | ☐ | ☐ | ☐ |
| 工厂方法（座位模板）* | 创建型 | ☐ | ☐ | ☐ | ☐ | ☐ | ☐ |
| 单例（锁管理器/配置）* | 创建型 | ☐ | ☐ | ☐ | ☐ | ☐ | ☐ |

\* 前 4 种为必做主力（≥3 种达标即得分，4-6 种全分析可拿"3 种以上 +1 分"加分项）

- [ ] 扩展性分析有具体结论：新增一种票价策略/通知渠道/订单状态，各改几行代码
